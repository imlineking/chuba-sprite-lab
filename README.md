# Chuba Sprite Lab

Современный локальный Windows-инструмент для превращения видео и последовательностей изображений в готовые игровые спрайт-листы.

**Автор и правообладатель:** Hanuman Media Company — Demidenko Dmitriy

**Год:** 2026

**Официальный репозиторий:** [imlineking/chuba-sprite-lab](https://github.com/imlineking/chuba-sprite-lab)

## Скачать

Откройте раздел [Releases](https://github.com/imlineking/chuba-sprite-lab/releases/latest) и скачайте единственный файл:

```text
Chuba-Sprite-Lab-portable.exe
```

Установка не требуется. FFmpeg, Sharp, локальная ИИ-модель и необходимые компоненты уже находятся внутри portable EXE. Для обновления откройте меню `?` в правом верхнем углу программы и нажмите **«Проверить обновления»**.

## Возможности

- MP4, WebM, MOV, MKV, AVI, GIF и наборы PNG/JPG/WebP;
- пакетная обработка нескольких видео по одним настройкам;
- наглядная очередь роликов, остановка после текущего файла и повтор только ошибочных задач;
- умная нарезка сложных спрайт-листов на отдельные объекты и запасной режим равномерной сетки;
- автоматические имена наборов без перезаписи существующих результатов;
- встроенный FFmpeg и полностью локальная обработка;
- анализ трёх контрольных кадров и объяснимая автонастройка;
- рекомендация локального ИИ при неоднородном фоне на краях кадра; запуск модели откладывается до предпросмотра;
- удаление белого, чёрного, зелёного, синего или автоматически найденного фона;
- локальная ИИ-очистка главного объекта без отправки кадров в интернет;
- умное удаление выбранной стены, пятна или просвета с поиском объекта во всей серии;
- редактор маски с кистями «Удалить» и «Защитить» для точной доводки;
- привязка PNG-элементов к одной или двум движущимся точкам с отслеживанием позиции, поворота и масштаба;
- очистка розового/маджента-ореола только по краю прозрачного силуэта;
- открытие выбранного кадра в Photoshop, Corel Painter, Krita или любом приложении через «Открыть с помощью»;
- быстрый переход в Photopea, Canva, Figma, Pixlr E или Pixlr X и замена кадра сохранённым результатом;
- возврат отредактированного PNG перетаскиванием прямо в окно кадра;
- сохранение защищённого тёмного контура при удалении чёрного фона;
- сравнение исходного и очищенного кадра;
- пять подложек только для предпросмотра: светлая клетка, белая, чёрная, зелёная и маджента;
- светлая и тёмная темы интерфейса с переключателем в заголовке и сохранением выбора; инструменты предпросмотра расположены под изображением и не закрывают края спрайта;
- разбор готового спрайт-листа на объекты или сетку и ручная правка рамок по изображению и координатам; исходный лист не меняется, в новом JSON сохраняются исходные прямоугольники и имена из соседнего JSON при их наличии;
- проверка размера силуэтов после сборки: предлагает пропорциональный масштаб для похожих поз и оставляет отличающиеся позы на ручную проверку;
- навигация по увеличенному предпросмотру инструментом «Рука»: удерживайте `Пробел` и перетаскивайте, не меняя сам спрайт;
- выделение объекта по прозрачности прямо в предпросмотре: пропорциональный и свободный масштаб, высота, ширина, наклон по X/Y, смещение, заполнение ячейки и уменьшение с полями;
- стабилизация по земле, центру или исходному движению;
- авторазмер ячейки и автоматическая сетка;
- экспорт PNG-атласа, отдельных кадров, JSON, отчёта и lossless WebP;
- по выбору — размер каждого листа в степени двойки; свободное место добавляется по правому и нижнему краю, координаты кадров в PNG и JSON совпадают;
- обратимое исключение кадров и диагностика скачков силуэта;
- проекты `.cslab`, восстановление незавершённой сессии и сохранение связанных исправленных кадров/PNG;
- история изменений с отменой и повтором, горячие клавиши и палитра быстрых команд;
- пользовательские профили экспорта;
- встроенная проверка обновлений GitHub Releases с обязательной SHA-256-проверкой;
- перерисовка кадров в пиксель-арт: палитры от Game Boy и PICO-8 до Commodore 64, дизеринг и пять стилей рисования — чистый, плоский тон, с контуром, штриховой тушью и стежком;
- помощник-питомец: сам смотрит на текущую работу и предлагает готовые решения одним нажатием, с объяснением и возможностью отменить; его можно скрыть;
- локальный ИИ лучше видит крупные кадры: кадр разбивается на перекрывающиеся тайлы, а режим качества выбирается («Быстро» / «Сбалансированно» / «Максимум» с зеркальной проверкой);
- порог силуэта подбирается по гистограмме самого кадра, а не фиксированными 50%;
- отчёт объясняет, что сделал ИИ: режим, число тайлов, выбранный порог, доля кадра под маской; подозрительные кадры попадают в предупреждения;
- проверка собранного набора: инспектор сверяет JSON с листом (координаты, хитбокс, теги, длительности, страницы) и показывает расхождения рядом с настройками атласа;
- хитбокс и точка опоры каждого кадра для Phaser 3, Godot 4 и TexturePacker — отдельным файлом `NAME.hitboxes.json`;
- экспорт не теряет предыдущий набор: новый результат записывается целиком и подменяет старый только после успешной сборки;
- сборка без интерфейса по файлу-рецепту и наблюдение за исходниками;
- встроенный пиксельный редактор одного кадра: карандаш, ластик, заливка с допуском, пипетка, отмена по мазкам, слои и палитра из самого изображения; сохранённый кадр сам становится заменой исходного.
- проводник задач предлагает путь по типу файла: разнести лист, изменить или вырезать объект, добавить кадры, собрать общий атлас предметов, выровнять размеры по опорному кадру, удалить фон или лишний объект; для каждого пути есть «Авто» и «Вручную»;
- режим «Тело на месте» удерживает плотную часть персонажа при длинной нити, хвосте или крыле, сохраняя полный силуэт в ячейке;
- бирюзовая сетка с шагом 10–500 пикселей при ручной разметке и в предпросмотре служит только направляющей и не экспортируется;
- нейтральная светлая тема в белых и серых тонах.
- тонировка спрайтов с сохранением прозрачности и светлотного рисунка (не переносит тени и блики).
- два режима удаления однотонного фона: только связанный с краем кадра или весь похожий цвет; предлагаемый контур виден в редакторе маски, где его можно поправить и защитить детали;
- пиксельная правка кромки: срезать 1/3 пикселя либо заменить почти белый край цветом с глубины 2/5 пикселей без изменения внутреннего рисунка.

Текущие ограничения упаковки, редактора, сборки и порядок дальнейшей работы перечислены в [техническом аудите](docs/TECHNICAL_AUDIT.md).

Карта входов, задач, автоматических шагов, ручных инструментов и выходных файлов: [docs/SCENARIO_MAP.md](docs/SCENARIO_MAP.md). В ней отдельно отмечены готовые пути и инструменты, которые ещё нужно разработать.

## Пиксельный редактор

Кнопка **«Пиксельный редактор»** под полосой кадров открывает выбранный кадр прямо в программе — без внешних редакторов и без промежуточных файлов. Что есть:

- **Рисование:** карандаш, ластик, заливка и пипетка; размер кисти 1–16, целочисленный зум, сетка по пикселям, клавиши `P`, `E`, `G`, `I`, `[` и `]`, `+` и `−`.
- **Отмена:** `Ctrl+Z` и `Ctrl+Shift+Z` (или `Ctrl+Y`). Шагом считается весь мазок целиком, а не отдельное движение мыши, и хранится только изменённый прямоугольник.
- **Слои:** видимость, замок, добавление и удаление. Заблокированный слой не принимает рисование и говорит об этом.
- **Палитра кадра** собирается из открытого изображения и предлагается готовыми образцами — по ней удобно подбирать цвет контура, не открывая ничего другого.
- **«Разброс»** задаёт допуск заливки: 0 — строго один цвет, больше — соседние оттенки. **«Стереть кайму»** убирает почти прозрачный ореол вокруг спрайта, который остаётся после удаления фона; без этого заливка фона с нулевым допуском останавливается на первом полупрозрачном пикселе.
- **Сохранение** (`Ctrl+S` или кнопка) кладёт кадр в папку программы и подставляет его вместо исходного — дальше он попадает в спрайт-лист как обычно. Исходный файл и видео не меняются.

Проект редактора и порядок дальнейших очередей (кадры и теги, выделение и трансформации, индексированная палитра, группы слоёв, автоматика конвейера) — в `docs/PIXEL_EDITOR_DESIGN.md`.

## Авто-режим и модели ИИ

Кнопка **«Разобрать кадры»** в блоке «Авто» измеряет настоящие кадры — не описание источника, а пиксели — и по этим числам выбирает инструмент для каждого шага. Рядом с шагом написано, почему он выбран, поэтому решение можно проверить, а не принимать на веру.

Что измеряется: однотонность фона по краю кадра и число цветов у края, доля полупрозрачных пикселей, длина границы относительно площади и плотность мелких деталей (мех, волосы, тонкие ремешки), доля ровных заливок и плавных переходов, реальные размеры кадра.

Как выбирается инструмент:

- фон однотонный (≥72 % непрозрачных пикселей у края и ≤3 цвета) — точный контур, **без модели**: он быстрее и ничего не придумывает;
- край сложный (длинная граница, полупрозрачные пиксели, высокая плотность деталей) — модель матирования, лучшая из установленных: BiRefNet HR matting → BiRefNet general → BiRefNet tiny → IS-Net → U²-Net → Silueta;
- много ровных заливок — стиль «чистый» без дизеринга; много плавных переходов — «плоский тон» с упорядоченным дизерингом; иначе стиль с обводкой. Размер блока считается от размера ячейки, число цветов — от числа цветов в кадре;
- кадр меньше ячейки — предлагается увеличение с восстановлением, и прямо сказано, что без него кадр растянется;
- в ролике меньше 8 кадров — предлагается интерполяция;
- атлас не влезает в лимит — страницы разбиваются автоматически.

Кнопка **«Применить план»** выставляет то, что есть в интерфейсе: режим фона, модель, качество и ускоритель, снятие ореола, параметры пиксель-арта. Остальные шаги конвейер делает сам при сборке. Шаг, для которого нужной модели нет, помечается как **«нужна модель»** и не выполняется молча.

### Модели: что в комплекте, что скачивается

В сборку входит только U²-Net small (4.5 МБ, Apache-2.0) — этого достаточно, чтобы инструмент работал сразу и без сети. Остальные веса скачиваются по требованию в папку `%APPDATA%\chuba-sprite-lab\models` (кнопка **«Открыть папку моделей»**):

| Модель | Размер | Лицензия | Задача |
| --- | --- | --- | --- |
| Silueta | 42 МБ | Apache-2.0 | маска, аккуратнее u2netp |
| U²-Net / U²-Net portrait | 168 МБ | Apache-2.0 | общая маска / портрет |
| IS-Net general / anime | 170 МБ | MIT / Apache-2.0 | чище контур; anime — для рисованных кадров |
| BiRefNet tiny / general / HR matting / portrait | 214 МБ … 1.02 ГБ | MIT | мех, волосы, тонкие детали |
| ViTMatte small / base | 109 МБ / 379 МБ | Apache-2.0 | уточнение готовой маски по тримапу |
| MobileSAM / SAM ViT-B | 20 МБ / 108 МБ | Apache-2.0 | вырезание объекта по клику |
| LaMa · RIFE · Real-ESRGAN · Depth Anything V2 | — | Apache-2.0 / MIT / BSD-3 | дорисовка фона, промежуточные кадры, увеличение, глубина |

Три вещи, которые проверяются отдельно и не выдаются одна за другую:

1. **Размер файла** сверяется с опубликованным для каждого файла — до установки;
2. **Контрольная сумма** SHA-256 сверяется, когда издатель её публикует (для части файлов она опубликована и записана в каталоге); иначе сумма записывается при загрузке на этом компьютере и в окне честно написано «сумма записана при загрузке»;
3. **Запуск**: кнопка «Проверить запуском» действительно загружает модель, прогоняет её на синтетическом кадре и проверяет, что ответ похож на маску. Только после этого в окне появляется «проверена запуском». Входной размер берётся из самого файла модели, а не из таблицы, поэтому другой экспорт той же модели тоже заработает.

Что не взято и почему (это записано и в коде, чтобы вопрос не открывался заново): **RMBG-2.0** — лицензия запрещает коммерческое использование, а инструмент распространяется вместе с игрой; **CodeFormer** — лицензия S-Lab только для некоммерческого; **GFPGAN** — лицензия свободная, но модель дорисовывает лицо по-своему, а у персонажа есть утверждённый эталон внешности.



## Язык интерфейса

Переключатель **«Язык интерфейса» / Interface language** находится в карточке «О программе» (кнопка «?» в заголовке окна), выбор запоминается вместе с остальными настройками. Русский — исходный язык: текст в разметке и в коде и есть ключ перевода, поэтому непереведённая строка остаётся русской, а не показывается служебным кодом. Английский сейчас покрывает окно, этапы работы, импорт, оба редактора кадра и карточку «О программе»; длинные пояснения и сообщения о ходе работы остаются русскими. Добавить строку — одна строка в словаре `src/i18n.js`, менять разметку не нужно.

## Помощник

Питомец в правом нижнем углу реагирует на текущее состояние: если лист больше лимита, у картинок нет прозрачности, у ролика избыточный FPS, силуэты «дышат» или у цикла плохой стык — он покажет карточку с объяснением и кнопкой **Применить**. Каждое действие можно отменить обычным `Ctrl+Z`. Рекомендации считаются локально и детерминированно: без сети и без модели. Кнопка **Скрыть** убирает питомца до следующего запуска, вернуть его можно кнопкой в том же углу.

## Сборка без интерфейса

На вкладке экспорта кнопка **«Сохранить рецепт сборки…»** записывает все текущие настройки в JSON. Тот же набор можно затем собрать командой:

```powershell
npm run cli -- --profile run.recipe.json            # собрать набор
npm run cli -- --profile run.recipe.json --dry-run  # проверить, ничего не записывая
npm run cli -- --profile run.recipe.json --watch    # пересобирать при изменении исходников
npm run cli -- --profile run.recipe.json --strict   # вернуть код 3, если инспектор нашёл ошибки
```

Неизвестные настройки в рецепте отвергаются, а не игнорируются: опечатка вроде `keymode` иначе молча дала бы другой результат. Если папка набора уже существует, команда не перезапишет её без `--clean` или `--version`. Коды выхода: `0` успех, `1` ошибка рецепта, `2` сбой сборки, `3` набор не прошёл проверку.

Ширину пула обработки можно зафиксировать в рецепте (`frameParallelism`, 1–8): по умолчанию она подбирается по числу ядер, а `1` делает обработку строго последовательной — полезно, когда важнее предсказуемая нагрузка на память, чем скорость.

## Пакетная обработка

Выделите несколько видео в окне выбора источника. Автонастройка и предпросмотр строятся по первому ролику, после чего выбранные параметры применяются ко всей очереди. Каждый ролик сохраняется в отдельную папку с именем исходного файла. Если имя занято, создаётся версия `-2`, `-3` и далее.

Ошибка одного ролика не останавливает оставшуюся очередь. Её можно мягко остановить после текущего ролика, а затем повторить только файлы с ошибками. В конце программа показывает число готовых наборов и список файлов, которые не удалось обработать.

## Проекты и быстрые команды

Команда **«Сохранить»** создаёт файл проекта `.cslab`. Исправленные кадры и привязанные PNG складываются рядом в папку `.assets`, поэтому работу можно продолжить после перезапуска. Последняя незавершённая сессия также предлагается на стартовом экране автоматически.

Основные сочетания: `Ctrl+O` — источник, `Ctrl+Shift+O` — проект, `Ctrl+S` — сохранить проект, `Ctrl+Z`/`Ctrl+Y` — история, `Ctrl+Enter` — сборка, `Ctrl+K` — палитра команд. В окне предпросмотра удерживайте `Пробел`, чтобы временно включить «Руку» и перемещать только область просмотра.

## Приватность

Программа сама не отправляет исходные видео, изображения, ИИ-маски или результаты обработки на сервер. U²-Net, нарезка листов, трекинг и ONNX Runtime работают локально. Интернет используется по прямому действию пользователя: для проверки обновлений либо открытия выбранного онлайн-редактора. Передача файла в Photopea, Canva, Figma или Pixlr выполняется пользователем в браузере.

Проверить интерфейс без рабочего стола можно встроенным режимом снимка: он рисует страницу в offscreen-буфере и сохраняет PNG, а в кадр не попадает ничего лишнего.

```powershell
npm start -- --screenshot shot.png
npm start -- --screenshot shot.png --screenshot-js сценарий.js   # выполнить сценарий перед снимком
```

Ускоритель локальной ИИ-модели переключается в блоке «Умная очистка». Значения по умолчанию (`Авто`) берут GPU, если он доступен, и молча откатываются на процессор. Проверить, что доступно на конкретной машине, и измерить это на своих кадрах можно двумя скриптами:

```powershell
node scripts/probe-ai-provider.mjs                        # что доступно и сколько стоит кадр
node scripts/benchmark-ai.mjs "путь\к\кадрам" 10          # реальные кадры: процессор против GPU
```

На машине разработчика (i7-12700KF, RTX 4060 Ti) чистый вывод модели ускоряется с ≈68 до ≈9 мс, но полный шаг на реальном кадре — только с ≈264 до ≈118 мс: большую часть времени занимают декодирование и масштабирование. Старт модели на GPU дороже примерно на 1,5 с, поэтому выигрыш начинается после десятка кадров. Те, кому важна побитовая воспроизводимость между разными машинами, ставят «Только процессор».

### Проверка на чистой машине

Собрать файл:

```powershell
npm run release:build
```

Затем на машине без Node.js и без установленных инструментов разработчика:

```powershell
cd release
.\Chuba-Sprite-Lab-portable.exe --self-test              # код 0 и отчёт chuba-self-test.json
.\Chuba-Sprite-Lab-portable.exe --screenshot shot.png    # интерфейс отрисовался
```

Обратите внимание на `.\`: без него PowerShell не ищет программы в текущей папке и отвечает «имя не распознано как имя командлета». И на то, что читать надо **файл отчёта**, а не вывод в терминал: portable-сборка работает в GUI-подсистеме и ничего не печатает. Путь отчёта задаётся `--self-test-report`.

`--self-test` проверяет Sharp, встроенный FFmpeg, наличие модели и реальный вывод ИИ с указанием ускорителя. Именно на чистой машине видно то, чего нет на машине разработчика: отсутствующий Visual C++ Redistributable для нативной части ONNX Runtime, отсутствие GPU-драйвера (Electron может не отрисовать окно на голой виртуалке) и поведение при первом запуске без кэша.

Тот же тест работает и из исходников — `npx electron . --self-test --self-test-report chuba-self-test.json`. Он проверяет те же пути, которые выбирает конвейер (`vendor/ffmpeg.exe` и модель из `models` или из папки загруженных моделей), поэтому отчёт из папки разработки сопоставим с отчётом portable-сборки, а не упирается в путь внутри Electron.
