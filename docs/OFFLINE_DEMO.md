# Офлайн-комплект Chuba Sprite Lab 1.8.0

Запускайте `portable/Chuba Sprite Lab.exe`. На флешку копируйте **всю папку portable**, включая resources и DLL. Node.js, Python и установка не требуются. Папка работает напрямую, без распаковки при каждом запуске. Внутренние ffmpeg.exe и компоненты Electron необходимы приложению.

## Состав

Все 14 рабочих моделей встроены: U²-Net small, Silueta, U²-Net, U²-Net portrait matting, IS-Net general, IS-Net anime, BiRefNet tiny/general/HR matting/portrait, LaMa, RIFE, Real-ESRGAN anime 6B и Depth Anything V2 Small. Веса занимают около 4,3 ГБ. Точные источники, размеры и SHA-256 находятся в `resources/models/bundled-models.json`.

Все реализованные локальные операции доступны без сети. Обновления, GitHub и внешние онлайн-редакторы используют интернет; для офлайн-правки есть встроенный редактор. ViTMatte и SAM остаются каталожными этапами в разработке и не выдаются за готовые инструменты. Помощник выбирает сценарии локальными правилами; отдельная языковая модель не используется.

## Помощник

Помощник живёт в отдельном окне рабочего стола. Перетащите его левой кнопкой мыши: позиция запоминается в профиле пользователя. Нажатие открывает команды в облаке. Кнопка помощника в заголовке возвращает его после скрытия. Он остаётся видимым при сворачивании приложения и закрывается вместе с ним. Имя берётся из учётной записи Windows, а не из имени компьютера.

## Диагностика

`Chuba Sprite Lab.exe --self-test --self-test-all-models --self-test-user-data C:\Temp\chuba-clean --self-test-report C:\Temp\chuba-models.json`

Команда проверяет реальный инференс всех 14 моделей с отдельным пустым профилем. `--desktop-probe C:\Temp\chuba-desktop.json` проверяет native-окна, перемещение, сохранение позиции, команды и анимацию облака. Диагностика не скачивает модели. На тяжёлых моделях проверка занимает несколько минут.

## Сборки

`npm run pack` создаёт папку portable через временную папку .build. Старые dist, release и portable сохраняются в .build-archive. `npm run release:build` дополнительно подготавливает многотомный архив для публикации; новый GitHub Release сам по себе не публикуется. Пересборка требует прямой команды пользователя, после неё обязательны verify, commit и push.

Коммерческий выпуск остаётся отдельным этапом: аудит лицензий и происхождения весов, требования FFmpeg и подпись приложения ещё требуют завершения.
