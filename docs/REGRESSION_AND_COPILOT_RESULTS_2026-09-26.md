# Регрессии и сравнение копилотов — 26 сентября 2026

Этот этап выполнен в исходниках. EXE не пересобирался; исходные игровые ассеты не заменялись. Проверки и изображения записаны в отдельную диагностическую папку.

## Исправления

- **Видео со звуком:** длительность выбранного видеопотока определяется по пакетам FFmpeg, отдельно от контейнера/аудио. Превью проверяет фактическое создание файла; у последнего кадра предусмотрены более ранние позиции поиска.
- **Повторная вырезка:** нарезка отдельных объектов помечает подготовленную маску. Автоматический режим сохраняет её RGBA, а не вырезает фон второй раз. Явный выбор другого метода остаётся доступен.
- **Общий фон:** автоматическая обработка видео и кадров одного листа фиксирует согласованный цвет фона по исходным образцам; он включён в ключ кеша. Разнородные независимые файлы анализируются отдельно.
- **Соринки:** близкие мелкие компоненты присоединяются к основному объекту с диагностикой. Далёкие подозрительно маленькие объекты, прошедшие исходный минимальный порог компоненты, сохраняются с предупреждением. Это геометрическая эвристика, не семантическое распознавание частей тела.
- **Шумный фон:** медиана каналов и допустимый разброс заменили решение по числу цветовых корзин. Лёгкий шум однотонного фона не требует тяжёлой сегментации.
- **Измерения контура:** нормализованная сложность, тонкие детали и мягкость измеряются на исходной маске до 16 Мп. Для более крупных файлов помечается уменьшенное измерение; оно само по себе не включает тяжёлую модель для сложного края.
- **Безопасные советы:** при Pixel Perfect переполнение предлагает страницы, не уменьшение; изменение контура/размера не предлагается как автоматическое исправление. Для разрыва цикла открывается редактор: ходьба не переводится автоматически в «туда-обратно». RIFE/увеличение не включаются автоматически для пиксельной графики.
- **Диагностика:** правила читают коды проблем. Повторы объединены по типу и анимации; полный список кадров сохранён и доступен в навигации. Русский текст предупреждения больше не является API.
- **Отмена:** весь совет с настройками и пересборкой превью — один шаг истории. Ctrl+Z и «Отменить совет» в настольном облаке возвращают настройки и прежнее превью. Применение автоплана с несколькими инструментами также отменяется одной операцией.
- **Ошибки:** весь план валидируется до изменения состояния. Неизвестные инструменты и ошибки выполнения видимы в облаке, есть повтор; неудачный план откатывается. Обновление анализа не скрывает ошибку выполнения.

## Qwen и Gemma: реальный локальный эксперимент

Добавлен экспериментальный селектор «Правила / Qwen / Gemma» в окне настольного помощника и кнопка сравнения. Контрольный режим остаётся по умолчанию. Модели работают через локальный Ollama, без чата, выбирают только существующие сценарии и подтверждённые измерениями советы. Ответ проверяется по схеме/реестру; выбранная пользователем задача имеет приоритет. При отсутствии модели или неверном плане — видимый возврат к правилам. Произвольные инструменты, команды и пути не исполняются.

RTX 4060 Ti 8 ГБ, RAM около 64 ГБ, Ollama 0.34.4. Проверены `qwen3-vl:4b-instruct` и `gemma3:4b`, около 3,3 ГБ каждая. В текущем Ollama Gemma 3n доступна без визуального входа, поэтому для одинакового теста изображений использована **Gemma 3 4B**. Модели запускались последовательно, освобождались после запроса; все три режима получали одинаковые измерения, миниатюры и цель. План сравнения не применяет изменения к ассетам.

| Случай / ожидаемая первая задача | Правила | Qwen | Gemma |
| --- | --- | --- | --- |
| Клубок / разнести лист | layout | layout | layout |
| Белка / явно выбрана анимация | animation | animation | animation |
| Разные объекты / отдельная правка или общий атлас | edit | batch | layout |
| БЗЗЗ на белом / правка или вырезка фона | edit | edit | layout |
| Ветка с запечённой клеткой / правка изображения | edit | background | layout |
| Белые цветы / явно выбрана правка | edit | edit | edit |

Первая задача совпала с ожидаемым набором: **правила 6/6, Qwen 4/6, Gemma 3/6**. Для смешанного набора batch может быть разумной альтернативой, но цель этой проверки — начать с выбора правки/атласа, не сразу пакетной очистки. Это небольшой набор сценариев, не универсальная оценка интеллекта; два случая содержат явную цель пользователя.

Время планирования: правила **<1 мс**, Qwen **4,064–4,441 с**, Gemma **4,686–6,025 с**. Общий анализ изображений выполнялся заранее и не включён в эти времена; это не время полного импорта или обработки. Здесь нейросети не показали преимущества, оправдывающего тяжёлый режим по умолчанию. Следующий этап — 20–30 случаев, слепая оценка альтернатив и сравнение завершения задач/числа ручных правок.

Ollama и веса установлены отдельно на тестовом ПК. В EXE их не добавляли. Перенос на чистый ПК требует runtime и локальных весов; отсутствие сети не мешает уже установленным моделям, но текущий переносимый комплект этим этапом не перепаковывался.

## ToonOut — отдельно от планировщика

Проведена реальная сегментация **исходного БЗЗЗ на белом**, большой ветки с клеткой и белых цветов. Сравнение с текущим BiRefNet Tiny: CPU, вход 1024, качество fast, автоматический порог, softness=0. ToonOut — официальный PyTorch, CPU, 6 потоков, стандартная нормализация и непрерывная альфа. Уже прозрачные области остаются прозрачными; исходный RGB сохраняется.

| Файл | ToonOut, CPU | BiRefNet Tiny, CPU |
| --- | --- | --- |
| БЗЗЗ | 14,298 с | 9,720 с |
| Ветка | 13,902 с | 7,406 с |
| Белые цветы | 13,434 с | 5,701 с |

Параметры методов не идентичны, времена включают разные пути подготовки/загрузки; это практический пробный запуск, не стандартизованный тест скорости. ToonOut заметно лучше удалил белый фон в просветах ветки и БЗЗЗ на этих примерах, сохранил основные молнии и белые лепестки. Однако некоторые белые островки/краевые остатки ещё видны. Ручной эталонной маски нет: IoU и процент «точности» не заявляются. Счётчик цветных пикселей в JSON — лишь вспомогательная диагностика; не измеряет сохранность белых/чёрных деталей.

Официальные веса: **885 046 394 байт**, SHA-256 `8c7f8a0bc24400f4caade76622f75ff22ca1e93e169add9d2b70093e2487fbe5`. HF revision `cbf720eca394edcde66b861a8a8c20fbabe9c748`; официальный код `MatteoKartoon/BiRefNet` commit `ba5d19a7bf16b1ea7746bb9e9bec83d97dad9709`. Код/веса заявлены MIT; лицензия обучающего набора проверяется отдельно. Показатель 99,5% из статьи относится к её набору/метрике, не к нашим файлам.

ToonOut пока **не включён в промышленный конвейер или EXE**. Для этого нужны проверка ONNX/провайдеров, памяти, размеров входа, порога альфы, лицензий распространяемого пакета и расширенный набор сложных контуров. Пользователь просил испытывать его отдельно: эксперимент завершён, выпуск не заявляется.

## Воспроизведение

Запуск из корня Sprite Lab, без команд упаковки:

```powershell
$env:CHUBA_AUX_MODELS = Join-Path (Get-Location) 'models'
npm run verify
node scripts/verify-live-assets.mjs '<game-root>' '<diagnostic-output>'
node scripts/verify-copilot-ui.mjs '<ui-output>' '<yarn-sheet>'
node scripts/compare-copilots.mjs '<cases.json>' '<comparison.json>'
python scripts/benchmark-toonout.py '<official-code>' '<official-weights>' '<matting-cases.json>' '<output>'
```

Формат случая планировщика: `{id, paths:[localFiles], expected:[taskIds], snapshot:{source,options,ui}}`. Формат случая ToonOut: `{id,path,reference?}`; reference — ручная RGBA-маска для IoU, если есть. Скрипты не изменяют входные изображения. Полные результаты эксперимента лежат в `docs/evidence/`; большие оригиналы и веса в Git не включены.

Первичные источники: [Qwen3-VL в Ollama](https://ollama.com/library/qwen3-vl), [Gemma 3n в Ollama](https://ollama.com/library/gemma3n), [Ollama generate API](https://docs.ollama.com/api/generate), [официальный ToonOut/BiRefNet](https://github.com/MatteoKartoon/BiRefNet), [веса ToonOut](https://huggingface.co/joelseytre/toonout), [статья ToonOut](https://arxiv.org/abs/2509.06839).
