# P1: единый маршрут очистки и сравнение инструментов

2 октября 2026. Продолжение [базовой проверки](P1_CLEANUP_BASELINE_2026-10-02.md). Реализовано в исходниках; EXE не пересобирался.

## Общий маршрут для одного PNG и группы

Автоматическая очистка сохраняет спорные светлые детали, но у неизменённых файлов с небольшими светлыми кандидатами предлагает следующий шаг: подтвердить отсутствие белого/серого в самом рисунке. Подтверждение перечисляет конкретные файлы и возможное удаление бликов/лепестков/пятен. Оно не открывается само и не перехватывает фокус; пользователь вызывает его из предложения. До согласия сильный проход не выполняется. После согласия используются существующее удаление остатков и локальная перекраска кромки. Белые контрольные файлы в группе не включаются в такое предложение.

Удаление конкретного цвета использует тот же `keyFrame` с `custom`, который уже служит для цветовой вырезки. Пипетка берёт настоящий sRGB-пиксель исходника, включая просмотр с масштабом; прозрачная подложка не является источником цвета. Пользователь выбирает цвет, допуск 0–255 и область «во всём рисунке» либо «только фон и просветы». Последняя сохраняет замкнутые детали выбранного цвета.

Подтверждение учитывает текущий просматриваемый файл, выбранные или все файлы. Группа получает один список на подтверждение, а каждый результат сохраняет собственный маршрут. Цветовые действия накапливаются; одинаковое действие повторно не добавляется. Явное удаление цвета не вызывает нейросетевую сегментацию. Отмена подтверждения не меняет пиксели; после согласия готовится просмотр, применение и сохранение остаются отдельными действиями. Undo возвращает группу одной операцией.

Основной список выбора ограничен автовыбором, ToonOut и BiRefNet Tiny. «Другие модели» раскрывает каталог без повторного вычисления уже готового результата. Специализированные LaMa/RIFE/Real-ESRGAN/Depth продолжают выполнять свои задачи; они не объединены с удалением цвета и не удалены из поставки.

Также исправлен перенос яркости/контраста/тепла из предыдущего набора: при загрузке других файлов значения начинаются с нуля.

## Сравнение на одинаковых исходниках

Семь реальных PNG, совпадающие SHA-256. Сравнивались текущий встроенный режим с подтверждёнными палитрами, явно выбранные ToonOut и BiRefNet Tiny. Подорожник в этом прогоне не запускался: здесь оценивается стадия очистки. ONNX-модели запрошены через DirectML; сообщения runtime о распределении операторов сохранены в логах.

| Способ | Сумма времени семи проходов | Наблюдение |
| --- | ---: | --- |
| Встроенная очистка, подтверждённая палитра | 2,26 с | У травы/подсолнуха убраны светлые остатки и перекрашен край; нейтральные детали белого контрольного файла сохранены |
| ToonOut | 36,43 с | Хорошо убрал фон подсолнуха и травы; дополнительно удалил заметную часть видимых светлых областей повреждённого белого цветка |
| BiRefNet Tiny | 59,11 с | У подсолнуха осталась белая кайма, у травы значительная часть остатков; у грибов детектор результата ещё находит около 29 876 кандидатов сетки |

Время включает вычисление и чтение/запись отдельного результата, но не генерацию HTML-превью; это не чистое время нейросети. Первый запуск модели включает её загрузку, другие приложения могли влиять на скорость. Это конкретный прогон, не общий рейтинг моделей. Число изменённых или удалённых пикселей не является точностью.

Контрольный `flowers_white_daisy_01.png` уже повреждён на входе. Из его 12 314 видимых нейтрально-светлых пикселей (alpha > 12, минимум RGB ≥ 170, разброс ≤ 55) встроенный защищённый проход не перевёл в прозрачность ни одного; ToonOut — 8 244, BiRefNet Tiny — 176. Это проверка сохранности видимого светлого материала по цветовому критерию, а не эталонная маска белых лепестков. Исходные повреждения нельзя приписывать этому прогону.

Вывод для текущего набора: известный цвет/палитра и уже подготовленная альфа сначала обрабатываются лёгким инструментом. Модель — альтернативный проход для сложной вырезки с проверкой, а не обязательный этап для каждого файла. Наличие многих моделей само по себе не улучшает результат.

## Проверки и воспроизведение

- `test/image-batch.test.mjs`: подтверждённый выбор по исходным индексам, сохранность соседнего файла, удаление цвета без доступной AI-модели, сохранение замкнутой детали в режиме фона, оригиналы не изменены.
- `scripts/verify-image-workflow-ui.mjs`: реальный путь подтверждения на траве/подсолнухе/белом цветке, отмена, применение/undo, пипетка с исходного пикселя, текущий/выбранный/все, раскрытие каталога без повторной обработки, обе темы и геометрия окна.
- `.diagnostics/p1-unified-cleanup-ui-2026-10-02-final-verification/`: итоговые снимки и `report.json`; пипетка проверена также при увеличении 4×.
- `.diagnostics/p1-tools-comparison-2026-10-02/`: `review.html`, `comparison.png` и `comparison.json`.
- `scripts/review-cleanup-corpus.mjs`: режимы `auto`, `confirmed`, `toonout`, `birefnet-tiny`; подтверждённые контрольные палитры читаются из `test/fixtures/cleanup-review-cases.json` и не являются правилами автовыбора.
- `scripts/compare-cleanup-tools.mjs`: строит сравнение существующих прогонов, проверяя совпадение входных хешей.

Итоговый `npm run verify`: 300 тестов, 299 пройдены, 1 пропущен, ошибок нет. Проверка приложения из исходников завершилась без исключений; сохранённый PNG совпал с принятым результатом, оригиналы не изменились.

Полностью самостоятельное различение белого материала и остатка фона, качество всех сложных масок и восстановление действительно отсутствующих RGB остаются отдельными задачами. Текущий шаг даёт работающий подтверждаемый маршрут, не обещание безошибочной очистки любой картинки.
