# Этап 2 — исправления конвейера

Дата: 2026-10-15. Версия исходников: 1.8.2 с локальными правками. Разрешение: пользователь «переходи к новому этапу» после первичного аудита. Объём этапа — подтверждённые A1 и A2; интерфейс и состав инструментов не переделывались. Portable EXE не пересобирался.

## Изменения

1. **A1: выключенная очистка фона.** Конвейер передаёт процессору поддерживаемый режим `alpha` вместо неизвестного `none`, который попадал в ветку удаления цвета. При выключенной отдельной очистке краёв исходные RGBA сохраняются. Включён `preserveFrameCanvas`: очистка больше не вписывает обычное изображение в неявную ячейку 600×400.
2. **A2: таймлайн между очисткой и упаковкой.** Источник порядка, имён анимаций, длительностей и опор — фактический манифест процессора, сопоставленный с выпущенными PNG. Упаковка не угадывает эти данные по именам `0000.png`. Несовпадение числа PNG и кадров манифеста останавливает конвейер с сообщением.
3. Перенесены имена клипов, их параметры, длительности кадров, точки опоры и число повторов. Обрезка прозрачных полей сохраняет `sourceSize` и `spriteSourceSize`; дедупликация не удаляет позиции таймлайна.
4. TexturePacker/Phaser JSON хранит длительности и теги; Phaser рассчитывает добавочные задержки с базовым интервалом не длиннее кратчайшего кадра. Godot получает относительные длительности и скорость своего клипа. Unity JSON получает длительности и параметры анимаций. При повторном импорте TexturePacker JSON сохраняется число повторов из `meta.animationLoop`.
5. **Ограничение Godot:** SpriteFrames задаёт только повторять/не повторять. Для конечного числа проходов больше одного экспорт показывает предупреждение на этапе результата и сохраняет его в `conveyor.json`; окончание после нужного числа проходов требует кода игры. Исходное число остаётся в манифесте процессора. Unity JSON — данные для интеграции, не автоматически созданный AnimationClip.

## Проверки и доказательства

До исправлений три новые сквозные проверки воспроизвели дефекты: PNG превращался в 600×400, непрозрачные GIF/APNG теряли все непустые кадры.

- `npm run verify`: **476 проверок, 475 прошли, 0 ошибок, 1 пропущена**. Лог: `verify-stage2-final.txt`.
- После последней правки сообщения об ограничении Godot: **25 связанных проверок прошли**, `npm run lint` прошёл. Логи: `stage2-regressions.txt`, `stage2-lint.txt`.
- Проверены точные RGBA и размер PNG; GIF и APNG с длительностями 80/240/120 мс, разными цветами, повтором первого изображения и конечным числом проходов; экспорт и повторный импорт; клипы с разными скоростями, опорами и прозрачными полями. Существующий golden-тест экспортов остался неизменным и прошёл.
- Повторены исходные пробы A1/A2 без перезаписи доказательств «до»: `stage2-probe.mjs`, `stage2-probe.json`, результаты в `stage2-output/`. Оба исходных GIF сохранили SHA-256; в атласе одна двухкадровая анимация с исходными 80/240 мс.

Тест тяжёлых LaMa/Real-ESRGAN/RIFE/Depth Anything V2 пропущен, как до правок. Реальная инференция моделей и воспроизведение в самих Phaser/Godot/Unity в этом этапе не проверялись. Проверен реальный локальный конвейер и его файлы, не только макеты зависимостей.

## Внешние отзывы

Grok ранее подтвердил направление после исправления фактических ошибок своего первого отчёта; это отзыв на аудит, не приёмка текущего diff. Итоговые отзывы DeepSeek и Qwen не получены: повторные чтения их вкладок завершились потерей отладочной сессии и тайм-аутом CDP. Не считать их молчание согласием. Пользовательские вкладки и настройки доступа не менялись; задания повторно не отправлялись.
