# Sprite Lab: первичный аудит Codex, 15 октября 2026

Статус: первичная техническая аналитика; отдельные аудиты DeepSeek, Qwen и Grok ещё собираются. Исходники приложения не изменены, EXE не пересобирался. Единственные новые файлы — материалы этой проверки.

## Договор задачи

Главный проводник — существующий настольный копилот. Он помогает получить результат короткими этапами: вход → цель → обработка → проверка → исправление → экспорт. Пользователь не должен выбирать модель или изучать каталог инструментов для обычной задачи. Сохранить Призму/Фарфор, рабочую студию, одобренную графику, исходники, обратимость и ручную доводку. Персонажный кукольный риг исключён. Технические подробности раскрываются по запросу. Внедрение — после разрешения пользователя на конкретные пункты.

## Приоритетные находки

### A1 · P0 · «Не убирать фон» всё же запускает цветовую очистку

`src/conveyor.mjs:processorOptions` передаёт `keyMode: "none"`, тогда как `src/processor.mjs:keyFrame` сохраняет исходную альфу только в ветке `alpha`; неизвестный `none` проходит в цветовую очистку. В реальном диагностическом GIF с непрозрачными кадрами preset.background=none завершился ошибкой «После удаления фона не осталось ни одного непустого кадра».

Предложение: согласовать контракт сохранения RGBA для всех маршрутов и выключателей очистки. Критерий: с выключенным удалением фона пиксели полностью непрозрачного PNG/GIF не исчезают, альфа и белые детали сохраняются; отдельный тест проверяет результат, а не только возвращённую строку настройки.

### A2 · P0 · Пересборка превращает одну анимацию в две и теряет длительности

Реальный `timing-shaped.gif` импортирован как два кадра (80/240 мс). После «конвейера» PNG собран, но Phaser JSON содержит две одно-кадровые анимации `0000` и `0001` с общим frameRate=8. Это видно в `timing-probe.json`. `createConveyorStages` заново упаковывает каталог очищенных PNG; `pipeline/build.mjs` выводит группы из имён и не переносит исходную frameMetadata по этому пути.

Предложение: передавать именованную последовательность, длительности, loop, исходный холст и pivots как данные между стадиями; не восстанавливать смысл серии только из `0000.png`. Критерий: GIF 80/240 мс → одна двухкадровая анимация с теми же паузами; аналогично проверить Aseprite tags, APNG и импортированный atlas JSON. Для них дефект пока является риском по тому же пути, а не отдельным выполненным тестом.

### A3 · P1 · Первый экран загружает каталог вместо показа следующего шага

Снимок `conveyor-image.png` (1280×820): после выбора PNG справа пять больших строк стадий, три из них пропущены; превью самого объекта нет, слева сразу группы инструментов с названиями моделей. Главное действие ниже прокрутки. `conveyor.js:renderDetection` выводит все допустимые группы, `planConveyorGuide` предлагает 5–6 действий в проверенных типах.

Предложение: центр — изображение/анимация, один главный следующий шаг, не более двух дополнительных действий; остальные инструменты сохраняются в раскрываемой студии. Список этапов компактный; название модели — в подробностях. Критерий: новый пользователь завершает PNG, видео и папку кадров через копилота без поиска кнопки ниже экрана; 1024×768 и обе темы.

### A4 · P1 · Состояние копилота и конвейера разнесено

`conveyor.js` владеет ui.busy, результатом и текущим режимом, `copilot.js` отдельно собирает busy из state.busy/applying/comparing/refreshing. `companion.js` запрещает все кнопки при state.busy, включая переданный chip cancel. Это конфликт контрактов; блокировка отмены именно в текущем реальном конвейере ещё требует отдельного UI-сценария, поскольку ui.busy может не попадать в состояние помощника.

Предложение: единое состояние активной операции/этапа, отдельное разрешение cancel, прогресс с именем файла, отмена вычисления и возврат к последнему результату. Критерий: кнопка отмены остаётся доступна при реальной очистке и проверке; остановка не оставляет интерфейс в busy; независимые задания не отменяются.

### A5 · P1 · Пресет для пиксельной графики меняет сам рисунок

`processorOptions` для pixelArt включает adaptive-пикселизацию, размер 4, палитру 32 цвета. Сам выбор игрового формата не должен автоматически превращаться в перерисовку утверждённого ассета.

Предложение: разделить «сохранить пиксельную графику» и намеренное «преобразовать в пиксель-арт». Критерий: упаковка принятого PNG без стилевой обработки сохраняет его RGBA; изменение стиля получает отдельный предпросмотр и отмену.

### A6 · P1 · Приёмка одного PNG пропущена

`capabilities.mjs` задаёт image только clean/export; `planConveyorGuide` прямо сообщает, что Приёмку не делает. Это технический факт, не доказательство плохой очистки каждого PNG. Для отдельных растений, глаз и светлых объектов такой вход основной.

Предложение: использовать существующие проверки маски и границ также для PNG: светлая/тёмная подложки, сохранение светлых деталей, подозрительные просветы, касание холста. Не требовать атласа для проверки картинки. Критерий: сомнительные области показаны и могут быть защищены, а не автоматически стёрты; отсутствие замечаний не называется художественной приёмкой.

### A7 · P1 · Ошибка экспорта ведёт к полному повтору

`copilot-conveyor.mjs` для любого failedStage предлагает несколько инструментов и общий run. В probe ошибка export вызывает рекомендации нарезки/очистки/упаковки. Возможность реального продолжения с промежуточного артефакта не подтверждена.

Предложение: рекомендация по причине и текущему этапу, повторить только незавершённое при неизменных входах; использовать существующий кеш обработчика. Критерий: после отказа папки вывода новый выбор папки не вызывает повторный inference/нарезку и не дублирует уже сохранённые результаты.

### A8 · P2 · Задуманные функции нужно объединить сценариями

Уже есть редактор серии/маски, геометрия, цвет, Подорожник, привязки, Aseprite/GIF/APNG, упаковка, рецепты CLI и очередь/watch. Их не нужно повторно изобретать. Не все специализированные инструменты доступны как этапы единого автоматического сценария; один только список capabilities не доказывает такую интеграцию.

Конкретный разрыв по коду: `conveyor.js:openInAdvanced` для кнопок инструментов заново импортирует исходные ui.paths через `source:dropped`, затем лишь переключает общую вкладку. Специальный переход есть для нарезки/приёмки, но кнопки редактора, OCR и других инструментов не вызывают соответствующий инструмент. Не доказано сохранение уже обработанного результата в таком переходе. Проверка готовности должна включать именно открытие нужного инструмента на текущем результате, а не только существование кнопки.

Предложение: единый реестр шага (вход, выход, область текущий/выбранные/все, отмена, стоимость, проверка), доступный студии и копилоту. Полезные дополнения: очередь сомнительных кадров с прямым переходом к исправлению; ограниченный повтор альтернативной очистки; повторяемый рецепт результата. Критерий: три сквозных сценария и одна общая история, без изменения цели набора «разные PNG» на «анимацию».

## Аналоги: что подтверждено документацией и полезно здесь

- Aseprite: теги и экспорт по тегам, длительности, CLI и preview. Перенять сохранение семантики анимаций и повторяемый экспорт; CLI/теги у нас частично уже есть, сначала устранить A2. https://www.aseprite.org/docs/cli/ ; https://www.aseprite.org/docs/tags/
- TexturePacker: проект/командная сборка, сравнение времён и smart-update hash, multipack. Перенять предсказуемую пересборку изменившегося, использовать имеющиеся рецепты/watch, не добавлять вторую очередь. https://www.codeandweb.com/texturepacker/documentation/commandline
- Pixelorama: кадры, onion skin и обратимые layer effects. Перенять контроль серии и обратимость; слои/редактор уже есть, нужность нового инструмента проверять на конкретном пробеле. https://pixelorama.org/user_manual/user_interface/timeline/ ; https://pixelorama.org/concepts/layer/

Это сравнение первичных документов, а не личное тестирование установленных аналогов и не гарантия их качества на наших ассетах.
