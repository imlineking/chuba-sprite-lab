# Сравнение присланных скриптов пикселизации

Проверено по двум присланным исходникам `pixelize.py` и `artistic_pixel_portrait.py` и по текущему `src/pixelate.mjs`. Цель — взять приёмы, полезные для Sprite Lab, сохранив прозрачность игровых ассетов и предсказуемость кадров серии.

## Обычная пикселизация

`pixelize.py` уже совпадает с фильтром Sprite Lab по основному конвейеру: уменьшение до сетки, извлечение палитры, фиксированные палитры, Bayer/Floyd дизеринг, обводка и увеличение без сглаживания. У нас есть дополнительный дизеринг Atkinson, режимы плоского тона и штриховой туши. Критическая разница: присланный скрипт сразу переводит изображение в RGB, теряя альфа-канал. Его насыщенность, контраст, автотон и резкость включены по умолчанию; на игровом портрете это заметно меняет исходные цвета. Такие коррекции должны оставаться выбором пользователя.

Добавлено сейчас:

- Своя палитра из 2–64 уникальных HEX-цветов. Образцы видны при вводе; значение сохраняется с проектом и рецептом CLI. Неверная палитра отклоняется до обработки.
- Необязательная чёткость деталей после уменьшения до сетки. Она действует только внутри полностью непрозрачной области, не меняет маску и отключена по умолчанию.

Следующий отдельный этап — точный целевой размер сетки W×H и экспорт 1×/2×/4×. Сейчас фильтр обязан возвращать исходные размеры кадра: от них зависят ячейки, координаты атласа и JSON. Одно поле ширины без согласования всего конвейера привело бы к неверным метаданным. Импорт палитры из PNG можно рассматривать вместе с палитрами документа; при импорте нужны ограничение числа цветов, явный порядок и работа с альфой.

## Художественный портрет

Второй скрипт предлагает более сильную идею: отдельно подбирать палитру кожи, волос, глаз и губ и подчеркивать ключевые черты после распознавания лица. Это потенциально делает портрет читаемее на маленькой сетке. Нынешний фильтр Sprite Lab не распознаёт лицо и не должен называться художественной перерисовкой.

Код нельзя безопасно включить без прототипа. `cv2.imread(..., IMREAD_COLOR)` теряет прозрачность. Сумма массивов точек двух радужек в `L[LEFT_IRIS] + L[RIGHT_IRIS]` не создаёт объединённую маску глаз. Выделение волос всей полосой над лбом захватывает фон. Обводка по цветам углов ненадёжна для прозрачных или пёстрых ассетов. FaceMesh обрабатывает только одно лицо, может ошибаться на рисунке и не закрепляет черты между кадрами анимации. В текущем окружении `mediapipe` отсутствует; результат именно этого скрипта на живом портрете не подтверждён.

Прототип запланирован в дорожной карте: локальное определение черт с проверкой уверенности, отдельные маски областей, сохранение RGBA, согласованность серии и безопасный возврат к обычному фильтру. Сравнивать следует на одинаковой сетке и нескольких типах портретов, отдельно оценивать лицо, волосы, силуэт, прозрачность, скорость и память.
