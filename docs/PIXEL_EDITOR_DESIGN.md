# Встроенный пиксельный редактор: проект

Документ описывает редактор целиком — модель данных, инструменты, слои, кадры, палитру, отмену,
интеграцию с конвейером и порядок внедрения. Составлен так, чтобы каждая следующая порция
возможностей **добавлялась к модели, а не переписывала её**. Список инструментов и поведение сверены
с Aseprite, LibreSprite, Pyxel Edit, GraphicsGale, Piskel и Pro Motion NG.

Первый этап уже реализован: внутренний редактор кадра с карандашом, ластиком, заливкой, пипеткой, слоями, палитрой и возвратом кадра в атлас. Остальные разделы описывают план, а не уже готовые инструменты.

## 1. Главное решение: документ редактора — это ещё один источник

Конвейер уже умеет работать с источником и выдавать «отрендеренную ячейку». Если редактор будет
редактировать **ту же самую ячейку**, а не заводить собственную вселенную, то атлас, хитбокс,
инспектор, экспорт, рецепт сборки и CLI продолжат работать без изменений.

Отсюда два режима входа:

| Режим | Что редактируется | Куда сохраняется |
|---|---|---|
| Правка кадра | одна ячейка текущего набора | `frameOverrides[sourceIndex]` — механизм уже есть |
| Новый спрайт | пустой документ или импортированный лист | новый вид источника `kind: "sprite"` |

Второй режим — это `source.kind`, который проходит через существующий пайплайн как обычные кадры.
Значит спрайт, нарисованный с нуля, можно сразу упаковать в атлас, проверить инспектором и
выгрузить в движок. Это то, чего нет ни в Aseprite, ни в Pyxel Edit по отдельности.

## 2. Модель данных

Модель — как в Aseprite, потому что она единственная, где слои, кадры и теги складываются без
костылей. Хранится как JSON рядом с проектом, изображения целов — отдельными PNG.

```
SpriteDocument
  width, height            # холст в пикселях, целые
  colorMode                # "rgba" (позже: "indexed", "grayscale")
  palette                  # массив #rrggbb + индекс прозрачности
  layers[]                 # порядок снизу вверх
  frames[]                 # длительность каждого кадра в мс
  tags[]                   # именованные диапазоны кадров
  cels[]                   # пересечение слоя и кадра
  gridSize                 # сетка кастомизации, как в Aseprite
  symmetry                 # none | x | y | both
  tileMode                 # рисование с заворотом для бесшовных текстур

Layer
  id, name, opacity (0..255), blendMode, visible, locked, kind
  kind: "normal" | "background" | "group" | "reference"
  parentId                 # для групп, вложенность произвольная

Cel
  layerId, frameIndex
  x, y, width, height      # цел может быть меньше холста
  imageRef                 # имя PNG в assets редактора
  linkedTo                 # id другого цела — общий рисунок между кадрами

Tag
  name, from, to, direction ("forward" | "reverse" | "pingpong"), repeat (0 = бесконечно)

Frame
  durationMs
```

Почему так:

* **Цел как пересечение** (а не «слой содержит кадры») — именно это делает добавление кадров и
  слоёв независимым: новый кадр не копирует всю структуру, а новый слой не требует пересборки.
* **Цел хранит свои границы и PNG отдельно** — большие холсты не обязаны быть плотными, а
  композитинг читает только нужные прямоугольники.
* **`linkedTo`** даёт «связанные целы» Aseprite: один рисунок на несколько кадров, что для
  спрайтовых наборов экономит память и правки.
* **Теги отдельно от кадров** — экспорт в атлас с тегами уже есть в конвейере, значит редактор и
  экспорт говорят на одном языке.

Правила инвариантов (проверяются при загрузке и после каждой команды): у каждого непустого цела
есть слой и кадр; `tag.from <= tag.to`; вложенность групп без циклов; `frameIndex` в границах.

## 3. Инструменты

Порядок — по важности, но все входят в план, чтобы не пришлось переделывать панель инструментов.

**Рисование**
* Карандаш (1 px), с режимом **pixel-perfect** — убирает «ступеньку» на диагоналях.
* Ластик, кисть произвольного размера и формы (круг, квадрат, горизонталь, вертикаль).
* Заливка: замкнутая область и глобальная; с допуском по цвету и режимом «только внутри выделения».
* Линия, прямоугольник, эллипс; контурные и залитые варианты.
* Градиент линейный и радиальный, с дизерингом (нужен для старых палитр).
* Штриховка/стёжка — узорный дизеринг кистью, поверх палитры.

**Выделение и правка**
* Прямоугольное выделение, лассо (свободное и полигональное), «волшебная палочка» с допуском.
* Перемещение выделения и всего слоя, смещение с заворотом.
* Трансформации выделения: отражение, поворот на 90°, масштаб с сохранением сетки (nearest).
* Пипетка; замена цвета по всему спрайту; замена по палитре.
* Осветление/затемнение (shading) — сдвиг по палитре вверх/вниз, а не арифметика над RGB.

**Помощники**
* Симметрия по X, Y и обеим осям (для персонажей — обязательна).
* Сетка и привязка к ней; изометрия — позже, если понадобится.
* Бесшовный режим (tile mode) с заворотом рисования.
* Калька соседних кадров уже есть в приложении — в редакторе она должна показывать именно
  соседние кадры документа, а не набора.

## 4. Слои

Добавить, дублировать, удалить, слить вниз, слить видимые, «свести» в один, переименовать,
переставить перетаскиванием, включить/выключить, закрепить, задать прозрачность.

Группы — вложенные, с собственной прозрачностью и blend-режимом (наследуются вниз).

Режимы смешивания: normal, multiply, screen, overlay, darken, lighten, add, subtract, difference.
Для пиксель-арта практически нужны первые четыре, но модель обязана хранить произвольную строку,
чтобы добавление режима было правкой таблицы, а не схемы.

Фон-слой: непрозрачный, не двигается, единственный. Отдельный тип нужен потому, что он меняет
правила экспорта прозрачности, и это дешевле заложить сразу.

Ссылочный слой (`reference`): виден, но не экспортируется и не выделяется пипеткой — как в Aseprite
для подложки-референса персонажа. Для вашего проекта это прямая польза: подложить утверждённый
эталон и рисовать поверх.

## 5. Кадры, теги, анимация

Добавить, дублировать, удалить, переставить кадр; длительность на кадр; теги с направлением и
повтором; воспроизведение с частотой набора; калька до и после (количество и прозрачность) — в
приложении калька уже есть, редактору нужен её внутренний вариант.

Экспорт наружу: теги редактора напрямую превращаются в именованные анимации конвейера. То есть
нарисованное в редакторе «run» само станет тегом в атласе.

## 6. Палитра

Загрузка и сохранение в GPL, ACT и PNG; встроенные палитры уже есть в `src/pixelate.mjs` —
переиспользовать их, а не дублировать. Сортировка, генерация рампы (свет→тень по базовому цвету),
правка по индексу, «прозрачный индекс», замена цвета по всей палитре.

Правка палитры должна применяться к рисунку сразу — это то, за что пиксель-артисты держатся за
индексированный режим, и ради этого стоит позже добавить `colorMode: "indexed"`.

## 7. Отмена

Стек команд над документом, а не снимки всей картинки: `PixelCommand { apply, revert, label,
coalesceKey }`. Мастихи кисти объединяются в один шаг по `coalesceKey` (слой + инструмент + мазок).

Связь с существующей историей приложения: редактор открывается как **под-история**, а на закрытии
отдаёт наружу одну команду приложения. Тогда `Ctrl+Z` в основном окне отменяет всю правку кадра
целиком, и две системы отмены не спорят.

## 8. Взаимодействие с конвейером (то, чего нет у других редакторов)

Это главная причина делать редактор здесь, а не в сторонней программе:

* «Обвести контуром» — контур по силуэту, вычисленному сегментацией, на новом слое.
* «Залить тенью» — второй тон по маске, а не по воображаемой лампе.
* «Взять палитру из спрайта» — медианное усечение, уже реализовано.
* «Перерисовать в пиксель-арт» — конвертер с палитрами, дизерингом и стилями уже готов; в редакторе
  он применяется к слою, а не ко всему кадру.
* «Показать в игре» — правка сразу видна в игровом масштабе: превью «В игре» есть.
* «Проверить кадром» — хитбокс и точка опоры пересчитываются по нарисованному, инспектор уже умеет
  их проверять.
* Правка идёт по кадру набора, поэтому нарисованное сразу участвует в атласе и выгрузке.

## 9. Что осознанно вне первой очереди

Тайлсеты и режим тайлов, скрипты (Lua/Aseprite API), bitmap-шрифты, плагины, несколько документов
вкладками, кривые анимации, слои-эффекты. Модель выше их не запрещает: тайлсет — это сетка поверх
документа, скрипты — доступ к тому же стеку команд, вкладки — массив документов.

## 10. Порядок внедрения

Каждая очередь — самостоятельная ценность и **не требует переделки предыдущей**.

| Очередь | Содержание | Состояние | Почему в этом порядке |
| --- | --- | --- | --- |
| 1 | Холст, зум и панорама, карандаш, ластик, заливка, пипетка, отмена, сохранение в кадр | **сделано** | Даёт рабочий инструмент и проверяет модель на практике |
| 2 | Слои (кроме групп), прозрачность, режимы смешивания, слияние | частично: список слоёв, видимость, замок, добавление и удаление | Без слоёв рисовать нельзя, а модель уже их описывает |
| 3 | Кадры, теги, калька, воспроизведение | нет | Превращает редактор из «правки кадра» в рисование анимации |
| 4 | Выделение, лассо, палочка, трансформации, симметрия | нет | Самые востребованные операции после рисования |
| 5 | Палитра как объект, индексированный режим, рампы | нет | Требует смены `colorMode`; раньше не нужна |
| 6 | Группы слоёв, ссылочные слои, сетка, бесшовный режим | нет | Удобство поверх готового |
| 7 | Автоматика конвейера (контур, тень, палитра, пиксель-арт по слою) | нет | Требует, чтобы всё предыдущее работало предсказуемо |

### Что уже работает в очереди 1

Документ живёт в главном процессе (`src/editor-session.mjs` над `src/sprite-document.mjs`), окно
держит только композит и список слоёв. Причина не в архитектурной красоте: окно загружается через
`file://`, где модульные скрипты запрещены, а операция на мазок передаёт прямоугольник, а не копию
холста. Состояние после любой команды одно и то же, поэтому перерисовка у окна одна.

Кроме перечисленного в очереди добавлены три вещи, без которых редактор бесполезен на кадрах этого
конвейера: «Разброс» (допуск заливки), удаление почти прозрачной каймы одним действием и палитра
кадра, собранная из самого изображения. Кайма — след удаления фона: полупрозрачные пиксели по краю
останавливают заливку с нулевым допуском, и без отдельной команды фон залить нельзя.


## 11. Производительность и рендер

Холст рисуется в `<canvas>` по целочисленному масштабу, кадр композитится в offscreen-буфер только
для видимой области. Перерисовка — по «грязным» прямоугольникам, а не целиком: на холсте 512×512 с
шестью слоями полная перерисовка на каждый мазок уже заметна.

Отмена хранит команды, а не копии изображений; для заливки и трансформаций команда хранит
затронутый прямоугольник и предыдущие пиксели только в его пределах.

## 12. Соответствие горячих клавиш

Как принято в отрасли, чтобы не изобретать: `B` карандаш, `E` ластик, `G` заливка, `I` пипетка,
`M` выделение, `L` лассо, `W` палочка, `V` перемещение, `Alt` временная пипетка, `[` `]` размер,
`X` обмен цветов, `Ctrl+Z` / `Ctrl+Shift+Z` отмена и повтор, `Shift` прямые линии и квадраты,
`Ctrl` замыкание выделения, стрелки — сдвиг на пиксель.
