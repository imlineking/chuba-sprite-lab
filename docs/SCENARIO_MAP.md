# Сценарии проводника: вход → намерение → действие → результат

Цель проводника — предложить **задачу**, которую пользователь узнает по своему файлу, и открыть одну следующую операцию. Он не должен делать вид, что знает творческий замысел: выбор конкретного объекта, желаемой позы и допустимой перерисовки остаётся за человеком. Автообработка показывает результат до сохранения; оригиналы не перезаписываются.

Состояния: **есть** — можно пройти путь в UI сейчас; **частично** — инструмент существует, но проводнику не хватает обнаружения или короткого перехода; **проект** — нужен новый алгоритм или интерфейс. Каждая подсказка должна показывать причину, затрагиваемые кадры, выбранный алгоритм и выходные файлы.

## Сигналы после первого превью

| Измерение/проблема | Подсказка автопилота | Предохранитель | Состояние |
| --- | --- | --- | --- |
| Видимый пиксель касается старой ячейки, соседний попадает в обрезку | Изолировать пиксели объекта маской, увеличить зазор, собрать новый лист | При реально слитых фигурах показать конфликт и открыть кисть, не угадывать границу | частично: маска компонента есть, диагностика слияния — проект |
| Размер тела скачет, а позы похожи | Предложить масштаб относительно выбранного эталона | Разные позы не масштабировать автоматически | есть |
| Центр рамки скачет из-за хвоста/крыла | Поставить «Тело на месте» | Не менять масштаб и не обрезать полный силуэт | есть |
| Непрозрачный фон/ореол/цветная кайма | Подобрать ключ, очистить RGB края, показать на белой/чёрной/зелёной/маджента подложке | Не менять исходник; не разрушать пиксель-арт без просмотра | есть |
| Сложный фон при хорошем простом ключе | Простой контур | Не загружать большую модель ради однотонного фона | есть |
| Сложный фон и тонкие детали | U²-Netp с настройкой края | Показать уверенность и участок для ручной правки | частично |
| Маска удаления не совпадает в соседнем кадре | Выделить подозрительный кадр | Не считать удаление успешным молча | есть |
| Мерцание после RIFE/ESRGAN/маттинга | Сравнение соседних кадров и ручное исключение этапа | ИИ не должен автоматически перезаписать серию | частично |
| Разрыв между концом и началом цикла | Предложить ping-pong или поправить кадр | Изменение цикла только после просмотра | есть |
| Атлас превышает лимит движка | Уплотнение, разделение страниц или уменьшение с прогнозом | Не уменьшать автоматически без визуального сравнения | есть |
| Неверный JSON/область вне страницы | Открыть инспектор ошибок экспорта | Блокировать заведомо неверный профиль | есть |
| Пропал исходный файл проекта | Показать путь и поискать замену по имени/хешу | Не подставлять похожий файл без проверки | проект |

## Следующие инструменты с наибольшей пользой

1. **Редактор объектов поверх исходного листа.** Показывать одновременно старые прямоугольники JSON, контуры и пересечения. Дать разделение/объединение компонентов, лассо и перетаскивание объекта на новую сетку. Текущая ручная сетка двигает рамки, а не пиксели; для соприкоснувшихся объектов нужен именно редактор маски/слоя.
2. **Контроль кадров на таймлайне.** Показать только кадры с обрезанием, скачком тела, пустой маской, загрязнённым краем или неуверенным трекингом. Щелчок открывает проблемную область, а не общие настройки.
3. **Согласование по отмеченным пользователем точкам.** Существующий выбор «центр/низ» — вычисляемая опора. Для крыльев и конечностей нужен инструмент поставить одну или две опорные точки на эталоне и соответствующие точки на других кадрах; затем показать предлагаемый перенос, поворот и масштаб до принятия. Рисунок тела не менять по умолчанию.
4. **Интерактивная свободная трансформация.** Встроенная панель уже даёт перенос, масштаб и сдвиг по X/Y, а объект можно тянуть мышью. Для перспективы по четырём углам и сохранения качества требуется отдельная операция с ручками, предпросмотром исходного контура и проверкой срезанных пикселей. Сдвиг по X/Y не следует называть перспективой.
5. **Безопасное удаление объекта из серии.** Пользователь показывает лишнюю область один раз; приложение сообщает уверенность переноса по каждому кадру. LaMa применять только в отмеченной области, где есть содержимое для восстановления; пиксельные кадры сверять на мерцание.
6. **Пакетные рецепты.** После удачной ручной правки предложить сохранить не просто параметры экспорта, а воспроизводимый рецепт задачи для папки/набора и применить его к похожим входам после проверки первого результата.
7. **Настоящее переосвещение.** Изменение оттенка или радиальная яркость не переносит старые тени. Для существующего спрайта нужен базовый цвет без освещения (albedo) и нормали; можно оценивать их из рисунка и глубины, но неоднозначность формы и уже нарисованные блики требуют сравнения с оригиналом и правки маской. При серии нормали и свет должны быть согласованы между кадрами. Отдельно полезен простой режим тонировки, но он должен называться именно тонировкой, а не переносом света.

## Правило выбора ИИ

Автопилот сначала выполняет дешёвые измерения и детерминированные операции. Модель предлагается лишь для этапа, где она может дать пользу: выделение сложного фона, заполнение явной маски, промежуточный кадр, увеличение малого рисунка или оценка глубины. В подсказке нужны причина, размер модели, локальное/сетевое состояние и обратимый результат. Нельзя автоматически угадать, какой из предметов пользователь хочет вырезать, считать разные предметы фазами анимации или дорисовать невидимые пиксели за слившимися объектами без его выбора.
