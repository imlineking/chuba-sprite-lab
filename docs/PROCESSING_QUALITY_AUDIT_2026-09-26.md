# Проверка обработки и качества изображений — 26 сентября 2026

## Вывод

Программа создаёт PNG, JSON, атласы и анимированные WebP. Однако успешная запись файла не означает хорошего изображения. На реальной фотографии автоматический план выбрал IS-Net General и почти полностью потерял человека; ручной BiRefNet Portrait с режимом clean дал пригодный пиксельный портрет. Удаление шахмат и белого по контуру повреждает белые лепестки. Эти случаи требуют исправления до обещания надёжной обработки одной кнопкой.

Qwen3-VL 4B и Gemma 3 4B сейчас выбирают сценарии. Они не рисуют пиксели и не вычисляют маску. При одинаковых настройках обработки шесть сценариев дали одинаковые RGBA во всех трёх режимах. В этом эксперименте выгоды для качества изображения от тяжёлых планировщиков не обнаружено. Следующий содержательный эксперимент должен измерять их выбор конкретных инструментов, проверку результата и исправление неудачной маски.

ToonOut испытан отдельно как инструмент вырезки. На сложной ветке он лучше Tiny; на контрольных цветах Tiny немного лучше по численному совпадению маски. Универсального победителя нет.

## Область проверки и ограничения

- Проверено приложение из исходников. EXE не пересобирался, переносимые сборки не изменялись. Этот отчёт не подтверждает новые свойства старого EXE.
- Основной запуск начат на коммите `80470325167f39cc89c24e40047e74ea14733944`. После двух найденных ошибок маршрутизации выполнены тесты и живой повтор запросов Qwen/Gemma.
- Основной профиль: CPU, fast, одинаковые настройки между планировщиками. Windows, Node 24.19, Ollama 0.34.4; на ПК RTX 4060 Ti 8 GB, но сравнение вырезки проводилось на CPU.
- Qwen: `qwen3-vl:4b-instruct`; Gemma: `gemma3:4b`. Это Gemma 3, а не Gemma 3n: выбранный установленный вариант 3n в данном runtime не поддерживает изображения.
- Проверены именно оригинальные исходники; их SHA-256 до и после основного прогона совпадают. Хорошие игровые файлы не заменялись.
- Оценки /5 — визуальное заключение на перечисленных случаях. Это не статистическая точность модели на всех изображениях.
- Для контрольных цветов есть известная исходная альфа. Для фотографии, БЗЗЗ! и сложной ветки ручной эталон маски не создавался: качество оценено визуально на бирюзовой подложке.
- Основной A/B исполнял заданную пользователем задачу с фиксированным профилем. Он не является свободным автономным исполнением произвольных команд нейромодели. Отдельно выполнен настоящий текущий автоплан для портрета.
- Новые веса в этой проверке не скачивались. Локальные специализированные модели и локальный Ollama использованы без облачного inference. Изоляция сети всей portable-сборки в этот прогон не входит.

## Численная проверка белых деталей

Контроль: известная альфа цветов, 5076 непрозрачных почти белых пикселей (все RGB >230). Сравнение бинарной маски при альфе >127. IoU — пересечение масок, делённое на их объединение; не «общая точность ИИ». Сохранность белого — доля этих 5076 пикселей, оставшихся непрозрачными.

| Фон | Инструмент | IoU | Сохранность белого |
| --- | --- | --- | --- |
| Белый | Цвет по контуру | 81,42% | **16,41%** |
| Белый | Весь цвет | 78,76% | 0% |
| Белый | U²-Net small | 69,74% | 99,65% |
| Белый | BiRefNet Tiny | **97,29%** | **99,72%** |
| Белый | ToonOut | 97,17% | 97,68% |
| Шахматы | Текущий checker | 88,02% | **31,74%** |
| Шахматы | U²-Net small | 84,64% | 69,11% |
| Шахматы | BiRefNet Tiny | **97,32%** | **99,63%** |
| Шахматы | ToonOut | 96,58% | 98,48% |

Режим «весь цвет» намеренно удаляет белые детали; его нельзя автоматически назначать там, где нужно сохранить цветы или молнии. Режим «по контуру» тоже не защищает белую деталь, если она соединена с наружным фоном. Высокая сохранность белого у Small при низком IoU объясняется оставшимся белым фоном внутри стеблей.

## Планировщики: правила / Qwen / Gemma

Выполнены шесть сценариев × три планировщика: портрет, БЗЗЗ!, атлас, видео, клубок, шахматы. В каждом одинаковые входы, цель, измерения и настройки обработки. RGBA совпал во всех шести случаях. Это подтверждает воспроизводимость общего исполнителя; не подтверждает одинаковую способность планировщиков выбирать маску при свободном поиске решения.

Найдены и исправлены два дефекта:

1. Лёгкие правила не предлагали `background` для одного изображения, поэтому явная цель очистки фона не становилась первой. Сценарий добавлен; пользовательская цель теперь соблюдается.
2. При отсутствии доступных советов JSON schema разрешала строку `none`, которую валидатор справедливо отвергал. Теперь разрешён пустой массив. Строгая проверка неподдерживаемых операций сохранена.

После исправлений оба случая снова проверены через живые локальные Qwen/Gemma: правильная первая задача, без fallback. Правила занимали менее 1 ms, запросы моделей — примерно 4,2–5,3 s. Общая подготовка измерений не входит в время правил. Холодный/тёплый запуск, память и скорость CPU ONNX против PyTorch не сравнивались в одинаковых условиях; выводы о превосходстве скорости не делаются.

Текущая интеграция VLM выбирает сценарий и поддержанные советы из списка. Конкретную маску текущий автопилот выбирает по измерениям/правилам. Важный следующий шаг — дать ему измеримый контроль уже полученного изображения и разрешённый повтор с другим инструментом.

## Остальные модели и ручные операции

- **LaMa: 4,5/5** на удалении дверной ручки из фото 320×320. Предмет исчез, фон восстановлен; пиксели вне маски совпали побайтно. Узкая маска и относительно простой фон, не проверка удаления больших объектов за человеком.
- **Real-ESRGAN: 3,5/5** на увеличении настоящего фото 96→384 против Lanczos. Стало резче и глаже, но лицо и цвета перерисованы. Не использовать автоматически для pixel-perfect ассетов или как восстановление достоверных деталей.
- **Depth Anything V2: 4/5** на относительной карте глубины фото: объект/фон читаются. Это не нормали, не доказанное 3D и не перенос освещения спрайта.
- **RIFE:** реальный этап интерполяции выполнен в основном прогоне. Успешный выход проверен; отдельная художественная оценка длинного цикла и согласованности мелких деталей не проводилась. Рекомендация для пиксельной ходьбы из этого теста не следует.
- **Прямоугольник и лассо:** удаление белого внутри области на оригинале БЗЗЗ!, все пиксели вне выделения сохранены побайтно.

## Приоритеты после измерения

1. **P0 — проверка результата маски и повтор.** Ловить почти пустой силуэт, крупную потерю деталей, подозрительные внутренние дыры. Показывать провал, пробовать другой подход; применять итог одной отменяемой операцией. Проверки одной доли альфы недостаточно: маленький исходный объект допустим.
2. **P0 — белые детали при шахматах/цветовом удалении.** Отличать структуру фона от белого объекта; защищать лепестки/молнии, проверять потери на контрольной альфе. При неоднозначности предлагать контур/выделение, не подтверждать готовность молча.
3. **P1 — выбор инструмента по содержимому и цели.** Фото человека → портретная вырезка; растительность/графика → проверенный кандидат; видео с несколькими предметами → выбор целевого объекта. Сначала исправить базовый исполнитель, затем измерять пользу VLM в этой роли.
4. **P1 — стилизация.** Shaded с сохранением оттенка кожи, полезный lineart, отдельный проверяемый stitch. Не выдавать простой фильтр за генеративную отрисовку.
5. **P1 — ToonOut как дополнительный инструмент.** Проверить переносимый runtime, память, лицензии и интеграцию отмены; переносить только при сохранении преимущества на разнообразных исходниках.
6. **P2 — большой набор и скорость.** 20–30 случаев, ручные эталоны сложных масок, повторяемые cold/warm-замеры, согласованность серии. Затем сравнить реальные автоматические решения Rules/Qwen/Gemma.
