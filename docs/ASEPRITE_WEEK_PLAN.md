# Отложенный этап: Chuba Sprite Lab рядом с Aseprite

План дополнен [дорожной картой копилота из 46 сценариев](COPILOT_SCENARIOS_ROADMAP.md): новые случаи отдельных PNG, масок, пакетной очистки и локального визуального планировщика. Крупные блоки этого документа сохраняются.

**Статус на 26 сентября 2026: крупные работы отложены; дата начала не назначена. Это план только для перечисленных ниже пробелов. Авторазнесение объектов, включая клубок, уже работает.** Aseprite — эталон ручного пиксельного редактирования. Chuba должен сокращать путь от готового листа, видео или набора картинок до исправленного атласа и данных для игры. Сравниваем рабочие сценарии и результат, а не количество кнопок. Сводные блоки и предварительные оценки активной работы — в [ROADMAP_1_8.md](../ROADMAP_1_8.md#отложенный-крупный-этап).

## Проверенная основа сравнения

Официальная документация Aseprite подтверждает: `.aseprite` сохраняет слои, кадры, палитры, теги и срезы; экспорт листа и CLI поддерживают JSON, packed layout, padding и extrude; есть выбор и трансформация частей рисунка, onion skin и tilemap. Исходники доступны, но условия Aseprite EULA запрещают свободное распространение собранного Aseprite. Не копировать и не включать его бинарник в Chuba.

В Chuba уже есть автоматическое разнесение объектов по связным пикселям, ручные рамки/координаты, визуальная сетка, новая сборка PNG + JSON, режим «Тело на месте», таймлайн, калька предпросмотра, редактор отдельного кадра со слоями/undo, игровые JSON для Phaser 3/Godot 4/TexturePacker/Unity и CLI. 26 сентября исходный `yarn-ball-roll-and-guide-6-frame-v2-review.png` проверен через действующий конвейер: найдены 6 объектов, созданы новый лист и JSON с 6 именами и исходными координатами; просмотр нового листа показал целые нити. Это **уже работающий сценарий клубка**, а не задача на следующую неделю.

Остающиеся пробелы: `packing=tight` использует полки, не MaxRects. Импорт Aseprite-подобного JSON пока читает прямоугольники/имена, но не гарантирует полный перенос длительностей, тегов, trim и опор. Опция `pixelPerfect` означает масштабирование без размытия; это **не** алгоритм Pixel Perfect для штриха кистью. Встроенный редактор не имеет произвольного выделения пикселей и не переключает кадры одной серии внутри себя. Это важно для **слипшихся или перекрытых** объектов, которые автоматический поиск не может разделить надёжно.

Источники: [формат файлов](https://www.aseprite.org/docs/files/), [CLI и параметры атласа](https://www.aseprite.org/docs/cli/), [выделение](https://www.aseprite.org/docs/selecting/), [onion skin](https://www.aseprite.org/docs/onion-skinning/), [tilemap](https://www.aseprite.org/docs/tilemap/), [лицензия](https://www.aseprite.org/faq).

## Целевой результат этапа

Пользователь открывает лист из Aseprite с JSON, сохраняет теги и длительности, а затем пользуется **уже готовым** разнесением объектов и получает новый атлас с согласованными метаданными. Для слипшихся объектов ему понадобится новый инструмент ручного выделения. Второй путь: открыть кадр в Aseprite через существующую команду «Открыть с помощью», сохранить PNG и вернуть его в Chuba; установленный Aseprite необязателен.

## Порядок работ и границы этапа

1. **Начало этапа:** зафиксировать три эталона: экспорт Aseprite с тегами/разной длительностью, уже работающий клубок как регрессионный пример, отдельный лист со слипшимися фигурами. Записать текущий размер атласа и JSON. Создать тест на импорт и повторный экспорт метаданных.
2. **Основная работа:** импорт JSON, затем MaxRects/extrude с тестами геометрии и проверки каждого игрового формата. Нельзя улучшить плотность ценой неверных координат или прозрачного края.
3. **Сложный лист:** дополнить существующие режимы выделением и переносом пикселей лишь там, где автоматические связные компоненты и ручные рамки не разделяют слипшиеся объекты. Сначала прямоугольник, затем связная «палочка»; лассо и свободная трансформация добавляются только если этот путь стабилен.
4. **Конец этапа:** короткий путь через помощника, ручной прогон трёх эталонов, светлая/тёмная тема, узкое окно, клавиатура, `npm run verify`, проверка JSON против PNG. Пересборка EXE запрещена до отдельной прямой команды пользователя.

Если P0 не проходит реальные эталоны, P1 не объявлять готовым и не расширять список инструментов за счёт качества результата.

## Следующая очередь после этого этапа

- Кадры и теги **внутри** редактора: переключение без закрытия окна, длительность кадра, калька и связанный cel. Основной таймлайн уже существует, но это не равно редактированию всей анимации в одном полотне.
- Лассо, симметрия, формы, Pixel Perfect именно для линии кисти; палитры как документ, индексированный режим и цветовые рампы.
- GIF/APNG для показа, необязательное взаимодействие с установленным Aseprite через его CLI, нативный импорт `.aseprite` после отдельной проверки полного round-trip. Tilemap/tileset и Lua API — только по конкретному игровому сценарию.
- Пул обработки/worker после измерений, затем углубление автоматических подсказок. Эти задачи не должны ломать уже работающий сценарий клубка и экспортных координат.
