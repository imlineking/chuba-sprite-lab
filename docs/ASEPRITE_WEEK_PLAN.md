# Неделя 28 сентября — 4 октября 2026: Chuba Sprite Lab рядом с Aseprite

**Статус: план, функции ниже ещё не реализованы.** Aseprite — эталон ручного пиксельного редактирования. Chuba должен сокращать путь от готового листа, видео или набора картинок до исправленного атласа и данных для игры. Сравниваем рабочие сценарии и результат, а не количество кнопок.

## Проверенная основа сравнения

Официальная документация Aseprite подтверждает: `.aseprite` сохраняет слои, кадры, палитры, теги и срезы; экспорт листа и CLI поддерживают JSON, packed layout, padding и extrude; есть выбор и трансформация частей рисунка, onion skin и tilemap. Исходники доступны, но условия Aseprite EULA запрещают свободное распространение собранного Aseprite. Не копировать и не включать его бинарник в Chuba.

В Chuba уже есть таймлайн, калька предпросмотра, редактор отдельного кадра со слоями/undo, импорт листа, игровые JSON для Phaser 3/Godot 4/TexturePacker/Unity и CLI. `packing=tight` использует полки, не MaxRects. Импорт Aseprite-подобного JSON пока читает прямоугольники/имена, но не гарантирует полный перенос длительностей, тегов, trim и опор. Опция `pixelPerfect` означает масштабирование без размытия; это **не** алгоритм Pixel Perfect для штриха кистью. Редактор не имеет выделения и не переключает кадры одной серии внутри себя.

Источники: [формат файлов](https://www.aseprite.org/docs/files/), [CLI и параметры атласа](https://www.aseprite.org/docs/cli/), [выделение](https://www.aseprite.org/docs/selecting/), [onion skin](https://www.aseprite.org/docs/onion-skinning/), [tilemap](https://www.aseprite.org/docs/tilemap/), [лицензия](https://www.aseprite.org/faq).

## Результат недели

Пользователь открывает лист из Aseprite либо готовый PNG, выбирает у помощника «Разнести объекты» или «Вырезать один объект», видит границы и риск срезания, вручную поправляет выбор при необходимости, затем получает новый атлас и согласованный JSON. Оригинал остаётся целым. Второй путь: открыть кадр в Aseprite через существующую команду «Открыть с помощью», сохранить PNG и вернуть его в Chuba; установленный Aseprite необязателен.

## Порядок работ и границы недели

1. **Начало недели:** зафиксировать три эталона: экспорт Aseprite с тегами/разной длительностью, клубок с длинной нитью, рисунок с открытым белым фоном и белыми деталями («БЗЗЗ!»). Записать текущий размер атласа, JSON и заметные дефекты. Создать тест на импорт и повторный экспорт метаданных.
2. **Основная работа:** импорт JSON, затем MaxRects/extrude с тестами геометрии и проверки каждого игрового формата. Нельзя улучшить плотность ценой неверных координат или прозрачного края.
3. **Ремонт листа:** минимально законченный инструмент выделения и переноса пикселей. Сначала прямоугольник, затем связная «палочка»; лассо и свободная трансформация добавляются только если этот путь стабилен. Предпросмотр показывает исходную и новую сетку, полный контур и запас вокруг него.
4. **Конец недели:** короткий путь через помощника, ручной прогон трёх эталонов, светлая/тёмная тема, узкое окно, клавиатура, `npm run verify`, проверка JSON против PNG. Пересборка EXE запрещена до отдельной прямой команды пользователя.

Если P0 не проходит реальные эталоны, P1 не объявлять готовым и не расширять список инструментов за счёт качества результата.

## Следующая очередь после этой недели

- Кадры и теги **внутри** редактора: переключение без закрытия окна, длительность кадра, калька и связанный cel. Основной таймлайн уже существует, но это не равно редактированию всей анимации в одном полотне.
- Лассо, симметрия, формы, Pixel Perfect именно для линии кисти; палитры как документ, индексированный режим и цветовые рампы.
- GIF/APNG для показа, необязательное взаимодействие с установленным Aseprite через его CLI, нативный импорт `.aseprite` после отдельной проверки полного round-trip. Tilemap/tileset и Lua API — только по конкретному игровому сценарию.
- Пул обработки/worker после измерений, затем углубление автоматических подсказок. Эти задачи не должны тормозить исправление клубка и экспортных координат.
